# Web UI for langgraph-adventure

**Date:** 2026-08-21
**Status:** design draft
**Owner:** michaelm96

## 1. Goal

Add a local-only browser UI on top of the existing CLI REPL so the same text-adventure game can be played from any device on the LAN without reimplementing the game graph. The web UI is a thin presentation layer; the existing `game_graph.py` and persistence remain the single source of truth.

## 2. Non-goals

- Authentication / multi-user accounts
- Multiplayer / shared sessions
- WebSocket / token-by-token streaming (phase 7 streaming already deferred — this UI shows full scenes per turn)
- Mobile-native UI (responsive but no PWA / install prompts)
- Production deployment (uvicorn locally only; no Docker, no reverse proxy, no TLS)
- Persistence exports, backups, or migration tooling

## 3. Architecture

A FastAPI app (`src/langgraph_adventure/web/server.py`) wraps the existing `langgraph_adventure.game_graph.graph` and `langgraph_adventure.persistence.get_checkpointer`. Each browser session corresponds to one `thread_id` (UUID stored in the URL query string `?thread=<uuid>`).

The CLI REPL and the web UI both drive the same compiled graph and the same `~/.langgraph_adventure/game.db` SQLite checkpointer. A `thread_id` created in the CLI is the same `thread_id` you can resume in the browser, and vice versa.

### Components

| File | Purpose |
|------|---------|
| `src/langgraph_adventure/web/__init__.py` | Empty package marker |
| `src/langgraph_adventure/web/server.py` | FastAPI app, routes, `thread_id` parsing, graph invocation |
| `src/langgraph_adventure/web/templates/play.html.j2` | Jinja2 layout: header, narration block, action buttons, history sidebar |
| `src/langgraph_adventure/web/templates/_narration.html.j2` | HTMX partial: append narration, swap action buttons, update history sidebar |
| `src/langgraph_adventure/web/static/style.css` | Minimal styling (~50 lines) |

No JavaScript framework. ~20 lines of vanilla JS for keyboard shortcuts (1/2/3 to choose, `u` for undo, `f` for fork).

### Dependencies (3 new, all already installed in the dev env)

- `fastapi` (0.118.0) — HTTP framework
- `uvicorn[standard]` (0.37.0) — ASGI server
- `jinja2` (3.1.4) — templating (already a transitive dep, made explicit)

Pinned in `pyproject.toml` under `[project.optional-dependencies] web = [...]`.

## 4. Routes

| Method | Path | Behavior |
|--------|-------|----------|
| GET | `/` | Redirect to `/play/new?theme=noir-detective` |
| GET | `/play/new?theme=<theme>` | Create thread_id, invoke meta-graph with theme, redirect to `/play/{thread_id}` |
| GET | `/play/{thread_id}` | Render play page (latest scene narration + actions + history sidebar) |
| POST | `/play/{thread_id}/action` | HTMX form submit: take action ID from form, invoke `graph.invoke(Command(resume=action_id))`, return `_narration.html.j2` partial |
| POST | `/play/{thread_id}/undo` | HTMX form submit: read previous checkpoint, call `graph.update_state(...)`, return `_narration.html.j2` partial |
| POST | `/play/{thread_id}/fork` | HTMX form submit: create new thread_id seeded from current state, redirect to `/play/{new_thread_id}` |

`thread_id` is a UUID4 generated by `uuid.uuid4()` on session start and stored in the URL (not in cookies, not in localStorage). No auth — anyone with the URL can play that thread.

## 5. Data flow

### New game

1. Browser `GET /play/new?theme=noir-detective` → server generates `thread_id = uuid4()`
2. Server compiles game graph: `graph = build_game_graph().compile(checkpointer=get_checkpointer())`
3. Server seeds state with the theme: `initial = {"messages": [], "current_scene": None, "chosen_action": None, "npc_dialogues": {}, "theme": theme}` (the `theme` field is read by the graph's `present_scene` node, which internally invokes the meta-graph to generate a `Scene` from it)
4. Server invokes: `graph.invoke(initial, config={"configurable": {"thread_id": thread_id}})`
5. The graph runs `present_scene → interrupt_for_choice`; `present_scene` produces the opening scene, `interrupt_for_choice` pauses awaiting the player's first action.
6. Server extracts state via `graph.get_state(config)`, builds narration + 3 action buttons from `state["current_scene"]`.
7. Server returns `play.html.j2` rendered with the opening scene + 3 action buttons.

### One turn (action chosen)

1. Browser clicks `[A] Open the door` → HTMX POSTs `/play/{thread_id}/action` with body `action=A`
2. Server reads state from checkpointer via `graph.get_state(config)`, validates `chosen_action` was set in a previous interrupt
3. Server invokes `graph.invoke(Command(resume=action_id), config=config)` — graph resumes from `interrupt_for_choice`, runs through `route_choice → react_npcs → merge_reactions → persist → next_scene → interrupt_for_choice` (pauses again)
4. Server extracts new state via `graph.get_state(config)`, builds narration + action buttons from `state["current_scene"]`
5. Server returns `_narration.html.j2` partial; HTMX swaps it into the page

### Undo

1. Browser `u` keypress OR click "Undo last turn" → HTMX POSTs `/play/{thread_id}/undo`
2. Server calls `graph.get_state_history(config)` → finds prior checkpoint's `values`
3. Server calls `graph.update_state(config, values=prior_values)` to rewind
4. Server returns `_narration.html.j2` partial with the previous scene rendered

### Fork

1. Browser `f` keypress OR click "Fork from here" → HTMX POSTs `/play/{thread_id}/fork`
2. Server reads current state via `graph.get_state(config)`
3. Server creates `new_thread_id = uuid4()`, calls `graph.update_state({"configurable": {"thread_id": new_thread_id}}, values=current_state.values)`
4. Server redirects to `/play/{new_thread_id}`

## 6. Error handling

| Failure | Handling |
|---------|----------|
| `thread_id` not found | 404 page with link back to `/play/new` |
| LLM call fails (rate limit, network, etc.) | Retry 3× with exponential backoff (1s, 2s, 4s). On final failure, render scene with `description="(the world is silent)"` and one action `[A] Try again`. Per spec §8. |
| SqliteSaver locked | Retry 3× with 100ms delay. On final failure, render `503` with retry button. |
| `interrupt()` not in `__interrupt__` (race) | Re-render current scene; tell player to pick an action. |
| Pydantic validation failure on LLM output | Retry with stricter system prompt. After 3 failures, fall back to a hardcoded "you can go left or right" scene. |
| Graph returns empty state (LLM produced nothing usable) | Render "you are in darkness" scene with one action `[A] Feel around`. |

All errors logged to stdout (uvicorn default) — no separate log file. Tutorial simplicity.

## 7. State management

- `thread_id` lives in the URL only — copy-paste to share a session.
- No server-side session store beyond what `langgraph`'s `SqliteSaver` already persists.
- No cookies, no JWT, no CSRF tokens. Same threat model as the CLI.

## 8. Testing

### Per-module demo

```bash
MOCK_LLM=1 python -m langgraph_adventure.web.server
```

Starts uvicorn on `127.0.0.1:8000`. Open `http://127.0.0.1:8000/play/new?theme=noir-detective` in a browser. Manual flow:

1. See opening scene + 3 buttons
2. Click `[A] Open the door` → narration updates, new buttons
3. Click `[B]` 3 more times → reach a terminal state
5. Click "New game" → back to `/play/new`
6. Open `/play/{thread_id}` for an old thread → resumes

Keyboard shortcuts:
- `1`, `2`, `3` → choose action A/B/C
- `u` → undo
- `f` → fork

### Automated tests

None for v1. The CLI REPL already exercises the same `game_graph` end-to-end under MOCK_LLM=1; the web UI is a thin HTML wrapper. Manual demo is sufficient for tutorial scope.

If we add tests later: `httpx.AsyncClient` against the FastAPI app, asserting HTML contains expected narration text after each POST.

## 10. Out of scope (explicit)

- **Auth** — anyone with the URL plays.
- **Multiplayer** — each thread is single-user.
- **WebSocket streaming** — narration shows full scenes per turn, not token-by-token. (Phase 7 streaming was already deferred for real-LLM use; web UI doesn't change that.)
- **Mobile UI** — responsive but no PWA / install / touch-specific gestures.
- **Production deploy** — local uvicorn only. No Docker, no nginx, no TLS, no env-based config.
- **Theming / skins** — single dark theme.
- **Save / load individual scenes** — full graph state via SqliteSaver; no per-scene snapshots.
- **Accessibility audit** — keyboard shortcuts work, but no screen-reader testing, no ARIA labels beyond defaults.

## 12. Success criteria

1. `python -m langgraph_adventure.web.server` (with `MOCK_LLM=1`) starts uvicorn on port 8000.
2. `GET /` redirects to a new game.
3. `GET /play/{thread_id}` renders an HTML page with narration + action buttons.
4. Clicking an action button POSTs and HTMX-swaps new narration in place — no full page reload.
5. `u` key triggers undo; `f` key triggers fork.
6. CLI-created `thread_id` can be opened in the browser; browser-created `thread_id` can be opened in the CLI.
7. `graph.get_state_history(config)` shows the same checkpoint history from either interface.
